Most frameworks log what an agent did. `agentsessions` keeps the run itself: an append-only,
hash-chained journal that reconstructs the session exactly, with no provider in the loop.

## How a turn runs

Almost every framework lets the agent call the provider, so the completion exists only in the
agent's memory and the log can describe a run but never rebuild it. Here the **host** makes the
call.

## On Kubernetes, a session outlives its pod

No substrate and no memory snapshot here: just `agentsessionsd`, a PersistentVolume, and a plain
Deployment. The pod is deleted mid-session, and a different pod replays the session byte-for-byte
and continues it. That is the whole claim, recorded against a real cluster.

## The surface you build against

Three contracts, one neutral wire form with a Go SPI. `Event` is shared by the log and the harness
stream, so what is journaled is exactly what the harness emitted.

<CardGrid>
  <Card title="Sessions" icon="seti:config">
    ```
    CreateSession   Exec      Fork
    GetSession      Replay    Suspend
    ListSessions              Resume
    ```
  </Card>
  <Card title="Harness" icon="seti:robot">
    ```
    Describe  the static contract
    Run       drive one turn,
              emitting typed events
    ```
  </Card>
  <Card title="Runtime" icon="seti:shell">
    ```
    Create    Restore   Stop
    Snapshot  Fork      Status
              Capabilities
    ```
  </Card>
</CardGrid>

`agentctl` is a thin shell over the same Go client your code would use, so each command is one call
on that API. With no `--server` it runs an embedded host over a local sqlite journal.

| | | |
| --- | --- | --- |
| `create` new session | `list` a project | `get` one session |
| `exec` a turn | `replay` free, no provider | `fork` at a seq |
| `suspend` release compute | `resume` continue | `version` build info |
</Reveal>

## Where a session can run

A harness declares what it needs to survive a resume; a runtime declares what it can provide.
`CanPlace` refuses an impossible pairing **before** provisioning compute.

| Tier | Needs | Runs on |
| --- | --- | --- |
| `STATELESS_REPLAY` | Nothing beyond the log | Anything, including a plain pod |
| `REQUIRES_MEMORY_SNAPSHOT` | RAM captured and restored | Memory-snapshot-capable compute |

**`runtime/local`** is filesystem-only and refuses a memory-snapshot harness rather than resuming
it wrongly. **`runtime/substrate`** runs both tiers against a real cluster on every pull request,
on gVisor and on a micro-VM. Kata, Cloud Hypervisor, and plain pods fit the same SPI but are not
shipped here.
</Reveal>

:::caution[Pre-1.0, and not yet secured]
No authentication, authorization, or transport security. `IdentityRef` is recorded as provenance
and never enforced, `project` is a filter rather than a tenancy boundary, and `DeleteSession` and
`Cancel` are declared in the proto but not implemented. `agentsessions.v1` is a proto namespace,
not a stability promise.
:::
